# CLAUDE.md

Working rules for Claude Code in this repo, on a laptop or in a cloud session. `README.md` covers setup and the
project structure. `SETUP.md` covers lead capture (GoHighLevel), Google Analytics and Meta.

## How changes ship

- Every push to `main` deploys the live site on Vercel. Never push to `main`.
- Each change goes on its own short-lived branch off `origin/main`, named `update/<topic>`, with a pull request.
  Vercel builds a preview deployment for every branch, so check the change there.
- `npm run lint` and `npm run build` must pass before the PR is opened.
- The site owner reviews and merges PRs. Don't merge unless asked. Before pushing more commits to a PR branch, check
  it's still open (`gh pr view <n> --json state`), because it may have been merged in the meantime.

## Copy

- Section copy, service outcome lines and card descriptions state what changes for the client: who finds them, how
  buyers see them, how deals close. Never list deliverables, tactics or how the work is done. Short descriptions are
  about two sentences.
- Don't invent claims: results, numbers, review counts, guarantees, how often we meet. If copy needs one that isn't
  already on the site, write a placeholder and list it in the PR for the owner to confirm.
- People in testimonials and client stories get their name and company only, with no job titles. Their quotes stay
  word for word.
- The reviews badge in `Hero.tsx` stays hidden (`SHOW_REVIEWS_BADGE = false`) until there are 50+ five-star reviews.

## Files made outside this repo

Some images and data are produced in Illustrator, After Effects or Premiere on the owner's Mac, by scripts that live
outside this repo. A cloud session can't remake them. Change the code and data around them, and if an asset needs
remaking, say so in the PR.

| Files | Where they come from |
|---|---|
| `public/services/<slug>.webp` | Service scenes, 1200×720 exports from the Illustrator card library. Replacing the file needs no code change. |
| `public/logos/clients/` and `src/lib/client-logos.ts` | Generated by `make_site_logos.py`. Don't edit by hand. |
| `src/lib/client-stories.ts` and `public/client-stories/` | Generated from `stories.md` by `build-site-stories.py`. Don't edit by hand. |
| `src/content/insights/N*.json` and `public/insights/<slug>/` | Insights posts, delivered from the video project. Copy changes go back through that project, not edits to the JSON here. |
| `public/industries/` and `src/lib/industry-hero-cards.json` | Hero scene cards, placed by percentage of the Illustrator canvas. |
| `public/testimonials/` | Posters and voice clips for the video testimonials. The videos play from Vimeo (`vimeoId` in `src/lib/testimonials.ts`). |

## Code

- One source of truth per area. Edit the data file, not the components that read it:
  - services and the four visitor goals: `src/lib/services-data.ts` (the services library, footer and industry pages read it)
  - industry pages: `src/lib/industries-data.ts`
  - funnel lead forms: `src/lib/lead-forms.ts`
- When a route or service slug changes, add a 301 in `next.config.ts` (the `oldServiceUrls` map handles old service
  URLs).
- `ServiceDialog.tsx` is the shared service pop-up. Pop-ups must scroll on short screens: the whole dialog on phones,
  the text column from `md` up (`max-h` in `dvh` units plus `overflow-y-auto`). Keep that in any new dialog.
- Icons come from `lucide-react` (pinned version). Industry "from → to" icons are mapped in `src/lib/shift-icons.ts`.
- Fonts are self-hosted in `src/app/fonts/`: Mangal Pro for headings (exposed as `--font-playfair` for historical
  reasons, not Playfair Display) and Inter for body text. Don't move them back to Google Fonts; builds failed
  intermittently when they loaded from there.
- Server-only secrets (`GHL_PRIVATE_TOKEN`, `META_CAPI_ACCESS_TOKEN`) never get a `NEXT_PUBLIC_` prefix. Never commit
  `.env.local` or any real key.

## Design

- Colours are theme tokens in `src/app/globals.css`. Use the tokens, not hex values:
  - `cream` (#F5F0EB): page background
  - `dark-green` (#1C3830): headings, nav text, footer and dark sections
  - `mid-green` (#4A7C59): accents, buttons, pill labels
  - `body` (#2D2D2D) and `muted` (#6B7280): text
  - `sage` and `deep-sage`: accents on dark green
- Sections are generously spaced (mostly `py-24` to `py-32`), with content about 1200px wide and centred.
- Check every layout change at phone width as well as desktop.

## Cloud sessions

- There is no `.env.local` in a cloud session. The site still builds, but lead form submissions fail (`/api/lead` has
  no GoHighLevel credentials), and the EmailJS copy and analytics are off. Test anything that needs them on the Vercel
  preview deployment, which has the Preview environment variables.
